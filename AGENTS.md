# AGENTS.md

## About

`ettun` is one self-contained Bash program (`bin/ettun`) that relays TCP over
Eternal Terminal. Its launcher, ET transport lifecycle, generated remote
supervisor, and cleanup protocol change together; `bin/README.md` explains
why they stay in one file. The README documents the public contract: usage,
configuration variables, and the adapter protocol.

## Layout

- `bin/ettun`: the command.
- `examples/transport-et-wrapper`: the tested reference `ETTUN_TRANSPORT`
  adapter.
- `install.sh`: generated; see below.
- `test/`: `run`, `install-test`, `ettun-{collision,custom,default}-test`,
  `ettun-fixture.sh` (sourced stubs), `lib/test.sh` (harness). See
  `test/README.md` for suite scope.

## Invariants

- User host and port values pass narrow validators; no user text is
  evaluated as shell. Targets are interpolated only into fixed positions of
  the generated supervisor; transport values are passed as argv.
- Fixtures use reserved example names (`gateway.example`,
  `service.internal`) and synthetic tokens.
- fwdports' `ettun` driver depends on this interface: it matches the
  `Usage: ettun VIA LOCAL_PORT TARGET TARGET_PORT`,
  `ettun VIA [--jump-host JUMP_HOST]`, and `Provider contract:
  remote-port-slot-v1` lines of `ettun --help`; it sets `ETTUN_TRANSPORT`,
  `ETTUN_REMOTE_PORT_SLOT_V1`, and `ETTUN_TRANSPORT_SINGLE_INVOCATION_V1`;
  and it queries its own transport adapter with the README's
  `ADAPTER --ettun-capabilities` protocol, requiring `connect-v2` for
  reverse routes. Keep all of these compatible.
- The README names Bash 3.2 as the minimum but says CI does not test it:
  there is no `macos-bash32` job and the macOS leg runs Homebrew Bash. On
  macOS, check with `PATH="/bin:$PATH" test/run`. `/bin/bash test/run` runs
  only the runner under 3.2: the suites and `bin/ettun` find `bash` on PATH.

## Testing

- Local: `test/run`. It lints the inventory's `program` rows when
  `shellcheck` is installed (skipping silently otherwise), then runs the
  suites hard-coded in `test/run`, in order. A new suite must be added to
  that list or it never runs, locally or in CI. Never parallelize them:
  they own process groups, pseudo-terminals, and loopback listeners.
- CI: `ETTUN_SKIP_SHELLCHECK=1 test/run`, on the full shared matrix
  (Linux, macOS, Termux) for every PR.
- Slow host: `ETTUN_TEST_TIME_SCALE=3 test/run`.
- Needs `python3` for the pseudo-terminal and socket fixtures. With `ncat` or
  `socat` installed, the real loopback cases run; otherwise they report a
  skip.
- `ettun-collision-test` statically rejects literal deadlines in the test
  tree (`monotonic() + N`, `timeout=N`, `read -t N`, `SECONDS + N`, sleeps of
  0.5 s or more, counted polls). Derive every wait from
  `ETTUN_TEST_WAIT_SECONDS` or `ETTUN_TEST_TIME_SCALE`.

## Test isolation

- No suite needs a real ET server; ET, relays, and process boundaries are
  stubbed by `ettun-fixture.sh`.
- `bin/ettun` writes a client identity under `XDG_STATE_HOME`, and its
  generated remote supervisor keeps relay state under `XDG_CACHE_HOME`. Run
  them in tests only with a scratch `HOME` and `XDG_STATE_HOME` (plus
  `XDG_CACHE_HOME` for supervisor cases), as the existing cases do.
- Temporary files stay under the guarded per-suite root from `lib/test.sh`.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local `test/run` does not detect this, and neither does the awk/xargs
  recipe in `test/README.md`. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`,
  where `<actions@lock>` is a cgraf78/actions checkout at the SHA in
  `.github/cgraf78-actions.lock`.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`; never edit it. Install logic lives in
  `support/install-checkout.sh`. After editing
  `scripts/checkout-installer.conf`, run `consumer-ci/sync.sh <this checkout>`
  from `<actions@lock>`.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename it.
